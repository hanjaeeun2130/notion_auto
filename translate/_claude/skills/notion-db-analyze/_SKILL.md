# notion-db-analyze

트리거 키워드가 없는 조회·분석 요청을 처리합니다.

**이 스킬에서는 Notion에 절대 쓰지 않습니다.** 페이지·DB 생성, 수정, 보관, 삭제를 하지 않고 `notion-writer` 도 호출하지 않습니다.

## 참조

- `docs/intent-catalog.md` — 요청 유형 → 조회 조건 → 제안 GWS 작업
- `docs/notion-db-schema.md` — 속성, 상태값, 담당자 → 이메일 매핑
- `.claude/rules/` — DB 목록과 ID
- `templates/report.md` — 보고 양식
- `.claude/agents/notion-analyst.md` — 조회·분석을 수행하는 읽기 전용 서브 에이전트

## 절차

### 1. 모드 확인

- 입력이 등록된 키워드의 `<키워드> : <내용>` 형식이면 분석 요청이 아님. notion-db-register 스킬을 사용
- 데이터 등록·변경 요청이면 여기서 처리하지 않음. 트리거 형식(예: `업무 : ...`)을 쓰도록 안내

### 2. notion-analyst로 조회·분석

`notion-analyst` 서브 에이전트를 다음 내용으로 호출합니다.
- 사용자의 요청 원문
- 현재 날짜, 시각, 시간대 (Asia/Seoul)

서브 에이전트가 요청 유형을 매칭하고, 조건을 변환하고, DB를 조회한 뒤 조회 조건 / 결과 항목 / 요약 / 제안 GWS 작업을 반환합니다.

조건 변환 기준 (서브 에이전트가 적용):

| 표현 | 조건 |
|---|---|
| 오늘 / 내일 / 이번 주 / 다음 주 | 날짜 = 변환된 날짜 또는 기간 (주 = 월–일) |
| ~까지 / 마감 | 마감일 ≤ 해당 날짜 |
| 지연 / 기한 지난 | 마감일 < 오늘 AND 상태 = 미완료 |
| 미완료 / 완료 / 취소 | `docs/notion-db-schema.md` 의 상태값 |
| <이름> 담당 | 담당자 = 일치하는 사람 |

### 3. 모호하거나 결과가 없을 때

- **모호함:** 서브 에이전트가 후보 해석을 반환하면 사용자에게 고르게 한 뒤 다시 조회
- **0건:** 사용한 조건을 보여주고 완화된 조건을 제안

### 4. 보고

`templates/report.md` 를 채웁니다.
1. 요청 요약 (원문 + 해석된 의도)
2. 조회 조건 (DB, 필터, 기준 시각)
3. 결과 표 (`# | 제목 | 날짜 | 상태 | 담당자 | 출처 DB`)
4. 제안 GWS 작업 (`# | 작업 | 대상 | 비고`)
5. 승인 요청: "전체 승인 / 번호 선택 / 수정 후 / 거절"

### 5. 승인된 작업 위임

- 승인된 GWS 작업 → 작업 번호, 유형, 대상, 내용, 근거 결과 항목과 함께 **gws-execute** 스킬로 넘김
- 거절했거나 작업이 없음 → 보고 후 종료

### 6. 기록

`runs/` 에 기록: 시각, 요청, 조회 조건, 결과 건수, 제안 작업, 승인 결정

## 예시

| 요청 | 조회 | 제안 작업 |
|---|---|---|
| 오늘 마감 작업 확인해줘 | Work, 마감일 = 오늘, 미완료 | 담당자에게 마감 알림 메일 |
| 이번 주 일정 정리해줘 | Personal Tasks + Work, 이번 주 | 주간 일정 Sheets |
| 지연된 작업 알려줘 | Work, 마감일 < 오늘, 미완료 | 담당자에게 독촉 메일 |

## 제약

- 이 스킬에서는 어떤 형태의 Notion 쓰기도 금지
- 이 스킬에서는 `gws` 명령을 실행하지 않음. GWS 작업은 승인 후 gws-execute 스킬로만 처리
- 조회 결과로 나온 것만 보고
