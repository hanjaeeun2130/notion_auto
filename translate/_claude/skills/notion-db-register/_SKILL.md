# notion-db-register

트리거 키워드로 결정된 항목을 매핑된 Notion DB에 등록합니다.

**미리보기에 대한 사용자 승인 없이는 어떤 것도 등록·수정·보관하지 않습니다.**

## 참조

- `.claude/rules/` — 키워드, 별칭, 대상 DB, DB ID, 기본값 (DB마다 규칙 파일 1개)
- `docs/notion-db-schema.md` — DB별 속성, 타입, 필수 항목, 선택지
- `templates/register-result.md` — 결과 보고 양식
- `.claude/agents/notion-writer.md` — 실제 쓰기를 수행하는 서브 에이전트

## 절차

### 1. 트리거 인식

- 형식: `<키워드> : <내용>`. 콜론 앞뒤 공백 허용, `:` 와 `：` 모두 인식
- `.claude/rules/` 파일의 키워드·별칭과 대조 (대소문자 무시)
- 콜론 형식이지만 일치하는 키워드 없음 → 등록된 키워드 목록을 보여주고 되묻기. 중단
- 내용에 수정·취소 표현(예: "취소", "변경", "cancel", "change to")이 있음 → 아래 **수정·취소 요청**으로 이동

### 2. 스키마 확인

- `docs/notion-db-schema.md` 에서 대상 DB 섹션 확인
- 없거나 오래되었으면 `notion-fetch` 로 DB 스키마 조회 (읽기 전용)

### 3. 내용을 속성으로 나누기

대상 DB에 있는 속성만 추출합니다.

| 속성 | 규칙 |
|---|---|
| 제목 | 날짜·시간·장소·담당자·후속 작업 표현을 뺀 나머지 내용 |
| 날짜 | 현재 날짜와 시간대(Asia/Seoul) 기준으로 실제 날짜로 변환: 오늘 / 내일 / 모레 / 토요일 (오늘 포함 가장 가까운 날) / 다음 주 월요일 / 11/20 (올해 기준, 이미 지났으면 확신 낮음 표시) |
| 시간 | 오후 3시 → 15:00, 15:00 → 15:00. 오전/오후 없으면: 1–6시 → 오후, 7–11시 → 오전, 12시 → 정오. 확신 낮음 표시 |
| 장소·담당자·우선순위 등 | DB에 해당 속성이 있을 때만. 담당자는 알려진 사람과 일치해야 하며, 아니면 확신 낮음 |
| 빠진 속성 | 해당 `.claude/rules/` 파일의 기본값으로 채우고 기본값 표시 (예: 날짜 없으면 오늘) |

### 4. 미리보기 전 확인

- **필수 속성:** 필수 속성이 여전히 비어 있으면 물어봄
- **선택지:** select / status 값이 기존 선택지에 없으면 가장 가까운 값을 제안하거나 물어봄
- **중복:** 같은 날짜에 같거나 거의 같은 제목의 항목이 있는지 DB 조회(읽기 전용). 있으면 미리보기에 표시

### 5. 후속 작업 분리

입력에 GWS 작업 요청(예: "팀장에게 메일 보내줘", "시트로 정리해줘")이 함께 있으면, 항목 내용에서 빼서 후속 작업으로 따로 정리합니다. Notion 항목에는 포함하지 않습니다.

### 6. 등록 미리보기 후 승인 받기

```
[등록 미리보기]
키워드: 업무 → DB: 업무일정
| 속성 | 값 | 근거 |
|---|---|---|
| 제목 | 기획안 제출 | 입력 |
| 날짜 | 2026-11-20 | 입력 "11/20" |
| 상태 | 진행 전 | 기본값 |
확인 필요: (확신 낮은 값, 중복 의심)
후속 작업: (있으면)
→ 승인 / 수정 (바꿀 내용 알려주세요) / 거절
```

- **승인** → 7단계
- **수정** → 변경 사항을 반영하고 미리보기를 다시 보여줌
- **거절** → 등록하지 않음. 중단

### 7. notion-writer로 등록

`notion-writer` 서브 에이전트를 다음 내용으로 호출합니다.
- 대상 DB (이름, ID)
- 승인된 속성값 (승인된 그대로)
- 입력 원문
- 승인 메모

### 8. 보고 및 기록

- `templates/register-result.md` 양식으로 보고: 키워드 → DB, 원문 표현과 함께 등록된 값, 페이지 링크, 기본값으로 채운 값, 수정·되돌리기 방법 (예: "개인 : 카페 약속 시간 4시로 변경")
- `runs/` 에 기록: 시각, 입력 원문, 미리보기, 승인, 페이지 ID, 결과

### 9. 후속 작업 위임

5단계에서 후속 작업이 있었다면 보여주고, 사용자가 승인하면 생성된 페이지 정보(제목, 날짜, 링크)와 함께 **gws-execute** 스킬로 넘깁니다.

## 수정·취소 요청

1. 키워드 DB + 제목(+ 날짜)으로 대상 행을 읽기 전용으로 조회
2. 대상 행과 변경 내용(새 값, 또는 취소면 "보관")을 보여줌
3. 승인 후 `notion-writer` 를 호출해 행을 수정하거나 보관. 취소는 상태 변경 또는 보관으로만 하며 삭제하지 않음
4. 여러 행이 일치하면 목록을 보여주고 사용자가 고르게 함

## 예시

| 입력 | 결과 |
|---|---|
| `개인 : 친구와 카페 약속 토요일 3시` | DB 개인일정 / 제목 친구와 카페 약속 / 날짜 다가오는 토요일 / 시간 15:00 (확신 낮음: 오전/오후 없음) / 상태 예정 (기본값) |
| `업무：기획안 제출 11/20 마감` | DB 업무일정 / 제목 기획안 제출 / 날짜 2026-11-20 / 상태 진행 전 (기본값) |
| `업무 : 주간회의 내일 오전 10시, 팀원들에게 메일 보내줘` | DB 업무일정 / 제목 주간회의 / 날짜 내일 / 시간 10:00 / 후속 작업: 팀원에게 메일 → gws-execute |
| `개인 : 카페 약속 취소` | 수정·취소 요청 → 행 찾기 → 보여주기 → 승인 후 보관 |
| `회식 : 금요일 7시` (없는 키워드) | 등록된 키워드를 보여주고 되묻기 |

## 제약

- 미리보기 승인 없이 등록·수정·보관 금지
- `.claude/rules/` 에 정의된 DB에만 쓰기
- Notion 페이지·DB 삭제 금지
- 이 스킬에서는 `gws` 명령을 실행하지 않음. 후속 작업은 gws-execute 스킬로 넘김
