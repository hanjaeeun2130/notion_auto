# 규칙: notion-회사

**Google 캘린더의 진흥원 관련 일정**을 Notion **회사** DB에 저장합니다.

> 우선순위: 이 규칙이 CLAUDE.md, 스킬, 에이전트, `config/`, `docs/` 와 충돌하면 이 규칙을 우선합니다.

## 대상

| 항목 | 값 |
|---|---|
| Notion DB | 회사 |
| DB ID | (DB 생성 또는 확인 후 채움) |
| 출처 | Google 캘린더 (GWS CLI 사용) |
| 일치 단어 | `진흥원` |
| 트리거 키워드 | 없음 — "진흥원 일정 가져와줘", "회사 일정 동기화해줘" 같은 요청으로 실행 |

## 다른 규칙보다 우선하는 사항

- **분석 모드 "Notion 쓰기 금지":** 이 요청은 트리거 키워드가 없지만 Notion에 씀. notion-db-analyze 로 보내지 않고 아래 동기화 절차를 사용
- **gws-execute "명령 미리보기 없이 gws 명령 금지":** 1단계의 Google 캘린더 **읽기 전용** 조회는 명령 미리보기 없이 gws-executor로 실행 가능. 그 외 `gws` 명령(생성, 수정, 삭제, 공유, 발송)은 기존대로 미리보기와 승인 필요

## 동기화 절차

1. **Google 캘린더 조회 (읽기 전용).** 사용자가 기간을 정하지 않으면 기본 기간은 오늘부터 30일. `gws calendar --help` 로 확인하고 `docs/gws-cli-reference.md` 에 기록된 읽기 전용 캘린더 목록 명령만 사용
2. **필터.** 제목, 설명, 장소에 `진흥원` 이 들어간 일정만 남김
3. **중복 제거.** 회사 DB를 읽기 전용으로 조회해, Google 캘린더 이벤트 ID가 이미 저장된 일정은 제외. 날짜·시간이 달라진 일정은 "변경"으로 표시
4. **동기화 미리보기:** `# | 제목 | 날짜 | 시간 | 장소 | 캘린더 이벤트 ID | 신규 / 변경`
5. **사용자 승인** (전체 / 번호 선택 / 수정 후 / 거절). 승인 없이 쓰지 않음
6. **notion-writer로 등록.** 신규 일정 → 행 생성. 변경 일정 → 행 수정. 각 행에 Google 캘린더 이벤트 ID 저장
7. 생성·수정된 페이지 링크를 **보고**하고 `runs/` 에 기록

## 속성 매핑 (제안)

| 회사 DB 속성 | Google 캘린더 필드 |
|---|---|
| 제목 | 일정 제목 |
| 날짜 | 시작 일시 – 종료 일시 |
| 장소 | 장소 |
| 메모 | 설명 |
| 캘린더 이벤트 ID | 이벤트 ID (중복 확인용) |

## 규칙

1. `진흥원` 이 들어간 일정만 회사에 저장. 다른 캘린더 일정은 이 규칙으로 어디에도 저장하지 않음
2. Google 캘린더 일정을 수정·삭제하지 않음
3. Notion 행을 삭제하지 않음. 캘린더에서 사라진 일정은 보고하고, 사용자 승인 후 보관만 함
4. 회사 DB가 아직 없으면 등록하지 않음. 사용자에게 알리고 생성을 제안 (notion-writer 작업 A, 승인 후). 참고: 채용 공고 트래커 아래의 "회사" 페이지는 이 DB가 **아님**
