# 규칙: notion-work

**업무 관련 할 일**을 Notion **Work** DB에 저장합니다.

> 우선순위: 이 규칙이 CLAUDE.md, 스킬, 에이전트, `config/`, `docs/` 와 충돌하면 이 규칙을 우선합니다.

## 대상

| 항목 | 값 |
|---|---|
| Notion DB | Work |
| DB ID | (DB 생성 또는 확인 후 채움) |
| 트리거 키워드 | `업무` |
| 별칭 | `일`, `work` |
| 기본값 | 상태 = 진행 전, 날짜 없으면 오늘 |

## 해당하는 항목

업무 할 일: 회의, 보고, 마감, 제출, 고객 연락, 프로젝트 작업

예시:
- `업무 : 기획안 제출 11/20 마감`
- `업무 : 주간회의 내일 오전 10시`

## 규칙

1. 키워드 `업무`(또는 별칭)가 붙은 입력은 **오직** Work 에만 저장
2. Google 캘린더에서 오는 **진흥원** 관련 일정은 Work 가 아니라 회사 DB에 속함 (`notion-company.md` 참고). `업무` 입력에 진흥원이 언급되면 미리보기에 표시: "진흥원 일정으로 보입니다 — 회사 에 저장할까요?"
3. 내용이 분명히 다른 분류에 속하면 사용자의 키워드를 유지하되 미리보기에 표시
4. 등록은 notion-db-register 스킬을 따름: 속성 나누기 → 미리보기 → 사용자 승인 → notion-writer
5. Work DB가 아직 없으면 등록하지 않음. 사용자에게 알리고 생성을 제안 (notion-writer 작업 A, 승인 후)
